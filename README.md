# 수영 강습 빈자리 알리미 (거의 실시간 버전)

동작구시설관리공단 삼일수영장 강습 페이지를 **약 25초 간격**으로 계속 확인해서,
'마감'이던 강좌에 빈자리가 생기면 디스코드로 스마트폰 알림을 보내줍니다.
컴퓨터를 켜둘 필요 없이 GitHub의 무료 자동화 서비스(Actions) 위에서 돌아갑니다.

## 준비물
- GitHub 계정 (무료)
- 디스코드 앱 (스마트폰에 설치, 알림 받을 용도)

## ⚠️ 이 버전은 저장소를 "Public(공개)"으로 만들어야 합니다

GitHub Actions는 원래 한 작업이 최대 6시간까지만 실행됩니다. 그래서 이 스크립트는
**5시간30분 동안 25초 간격으로 계속 확인하다가 스스로 끝나고, 5시간마다 새 작업이
자동으로 이어받는** 방식으로 24시간 감시를 흉내냅니다.

문제는 비공개(Private) 저장소는 한 달 무료 실행 시간이 2,000분뿐이라, 이렇게
거의 상시로 돌리면 며칠 안에 소진되어 버립니다. **공개(Public) 저장소는 실행
시간이 무제한 무료**이므로, 이 방식을 쓰려면 저장소를 Public으로 만들어야 합니다.

- 코드 자체에는 개인정보가 없고, 디스코드 웹훅 주소는 Secret으로 분리되어
  코드에 노출되지 않으니 실질적인 보안 위험은 없습니다.
- 다만 저장소가 공개되면 누구나 코드와 실행 로그를 볼 수 있다는 점은 참고하세요.

---

## 1단계. 디스코드 웹훅 만들기 (알림 받을 주소)

1. 디스코드 앱에서 (없다면) 서버를 하나 만듭니다. 왼쪽 아무 서버나 있어도 되고,
   없으면 좌측 하단 `+` 버튼 → "직접 만들기" → 아무 이름으로 생성.
2. 알림 받을 채널을 하나 만들거나 기존 채널(#일반 등)을 사용합니다.
3. 채널 이름 옆 톱니바퀴(채널 편집) → **연동(Integrations)** → **웹후크(Webhooks)** → **새 웹후크**.
4. 이름은 아무거나 (예: 수영알리미), **웹후크 URL 복사** 버튼을 눌러 URL을 복사해둡니다.
   `https://discord.com/api/webhooks/...` 형태의 긴 주소입니다. 이 주소는 절대 남에게 공유하지 마세요.

## 2단계. GitHub 저장소 만들기

1. https://github.com 에서 회원가입/로그인.
2. 오른쪽 위 `+` → **New repository**.
3. 이름은 아무거나 (예: `swim-watcher`), **반드시 Public**으로 설정 → **Create repository**.
   (이미 Private로 만들었다면 Settings 맨 아래 **Danger Zone → Change visibility → Make public**에서 바꿀 수 있습니다.)

## 3단계. 파일 업로드

1. 방금 만든 저장소 페이지에서 **Add file → Upload files** 클릭.
2. 이 zip 안의 파일/폴더를 전부 그대로 끌어다 놓습니다.
   (`watcher.py`, `state.json`, `.github/workflows/watcher.yml`, `README.md`)
   - `.github` 폴더가 안 보여도 정상입니다. 브라우저로 폴더째 끌어다 놓으면 경로가 그대로 유지됩니다.
3. 하단에 커밋 메시지 아무거나 입력 후 **Commit changes**.

> 만약 브라우저 업로드에서 `.github/workflows/watcher.yml` 경로가 깨진다면,
> 저장소 화면에서 **Add file → Create new file**을 누르고 파일 이름란에
> `.github/workflows/watcher.yml` 이라고 직접 입력한 뒤, 이 파일 내용을 복사해 붙여넣어도 됩니다.

## 4단계. 웹훅 주소를 비밀값(Secret)으로 등록

1. 저장소의 **Settings** 탭 → 왼쪽 메뉴 **Secrets and variables → Actions**.
2. **New repository secret** 클릭.
3. Name: `DISCORD_WEBHOOK_URL`
4. Value: 1단계에서 복사한 웹훅 URL 붙여넣기 → **Add secret**.

## 5단계. 자동 실행 켜기 & 테스트

1. 저장소의 **Actions** 탭 클릭. "I understand my workflows, go ahead and enable them" 같은 버튼이 있으면 눌러서 활성화.
2. 왼쪽에서 **Swim Class Watcher (real-time loop)** 클릭 → 오른쪽 **Run workflow** 버튼 클릭.
   이때 나오는 `test_seconds` 칸에 `60` 정도를 입력하면, 5시간30분이 아니라 딱 60초만 돌려보고
   끝나므로 테스트하기 편합니다. 비워두면 정상 모드(5시간30분)로 실행됩니다.
3. 잠시 후 실행 로그를 열어보면 몇 초 간격으로 확인하는 로그가 계속 쌓이는 게 보입니다. 정상.
4. `test_seconds`를 비워두고 다시 한 번 **Run workflow**를 눌러 정식으로 시작하세요.
   이후에는 5시간마다 스스로 이어받으며 계속 돌아가고, 빈자리가 새로 생긴 강좌가 있을 때만
   디스코드로 알림이 옵니다. (맨 처음 확인 때는 현재 상태를 저장만 하고, 그 다음 확인부터
   "새로 생긴" 빈자리만 알려줍니다.)

### 실행 중인지 확인하는 법
Actions 탭에 들어가면 지금 돌고 있는 작업이 초록 점(진행 중)으로 표시됩니다.
5시간마다 이전 작업이 자동으로 취소되고 새 작업이 시작되는 것도 정상 동작입니다
(빈틈없이 이어받기 위한 설계입니다).

## 감시 범위 바꾸기

지금은 삼일수영장의 "강습수영(단체)" 전체 강좌를 감시하도록 되어 있습니다
(`watcher.py` 상단의 `PARAMS_COMMON`). 다른 지점이나 종목을 보고 싶으면
사이트에서 원하는 조건으로 검색한 뒤 주소창의 `center=`, `category1=` 값을
바꿔서 `watcher.py`의 값도 똑같이 바꿔주면 됩니다.

## 확인 주기 바꾸기

`.github/workflows/watcher.yml` 안의 `CHECK_INTERVAL_SECONDS: "25"` 값을 바꾸면
확인 간격이 바뀝니다 (예: 10으로 바꾸면 10초마다). 너무 짧게 하면 사이트에
부담을 줄 수 있으니 10초 이상을 권장합니다.

`RUN_DURATION_SECONDS`(현재 19800초 = 5시간30분)와 `cron: "0 */5 * * *"`(5시간마다
새로 시작)는 서로 맞물려 있으니, 굳이 바꿀 필요는 없습니다. 그대로 두면 자동으로
이어받으며 계속 돌아갑니다.
